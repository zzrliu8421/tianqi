## 0. 结论速览

1. **工程上，这是一个完成度不低的个人产品；研究上，它目前还不是一个"研究项目"。** 没有研究问题、对照基线、测量数据和结论边界，而青科协评分表中"科学性 + 创新性"合计约 60 分。
2. **全国赛 2025 年起已不再评审作品**：15–24 岁、经省级关联赛事推荐、现场做挑战任务。因此"作品评审"实际发生在市赛/省赛；未满 15 周岁无法参加全国赛。
3. **本轮改造已落地 9 项工程债修复**，其中最关键的三个是：修复会让演示卡死的并发死锁、修复"WebGL 渲染器一直静默失败"的探测 bug、把代理从开放中继收紧为白名单 + 限流 + Origin 校验。

### 1.2 架构

三套链路，比"天气 App"这个标签复杂：

- **数据链**：免 Key 直连 Open-Meteo / geolocation-db / ipify；需要 Key 的走高德、和风、IPnews。中国区实际是"高德实况 + Open-Meteo 预报/AQI"的混合，港澳台与海外另有分流顺序，带 5 分钟/30 分钟内存缓存与请求取消。
- **定位链**：并行探测公网 IP（Cloudflare + ipip，4s 超时）→ 纯 IPv6 走 IPnews → IPv4 且配置高德则直接 v3/ip（显式传 IP 防边缘节点出口误判）→ 回退 GeoDB → 按 IP_PROVIDER_ORDER 兜底。
- **渲染链**：Three.js 8 种天气主题 + 昼夜插值 + UnrealBloom + 颜色分级 Pass；WebGL 不可用时回退约 1,500 行 Canvas 2D 引擎。

后端两套等价实现（Node 代理 / EdgeOne 边缘函数），路由表一致；边缘侧带 120 秒 Cache API；Key 收敛在服务端，前端 config.js 只有布尔值。

### 1.4 问题清单（改造前）

**P0：会导致演示翻车或安全事故**

1. **isLoading 死锁**：loadByIP / loadWeather 先取消旧请求、再判断 isLoading 并 return。页面加载后自动定位的 1–3 秒内点搜索，或连续点两下刷新，会让第一次请求的 finally 因 token 不匹配而不复位 isLoading，页面永久停在骨架屏。
2. **API Key 历史泄露**：旧分支 origin/main 的 7 个提交把 32 位高德 Key 明文写在 index.html 中，与当前 .env 中仍在使用的是同一把；旧版 build.js 还会把真实 Key 写进公开可访问的 config.js。必须轮换。
3. **代理是开放中继**：/api/amap/* 不限路径、不限流、CORS 为 *，任何站点都能借 Key 刷额度。
4. **自建模式静态泄露**：server.js 会返回 /.git/config 与 /node_modules/...，仅拦截了 .env。
5. **README 与实现不符**：GPS 定位未实现、PWA 仅 3 个 meta、自定义景深是未使用参数、reduced-motion 对 WebGL 无效、AQI 说法不准确。

**P1：影响体验、性能与答辩**

6. 移动端降级不彻底：FPS 自适应只裁雨雪粒子，不动分辨率、Bloom、云层——而填充率与 overdraw 才是瓶颈。
7. 首屏约 1.5MB 未压缩；vendor/ 全量拷贝 556 文件 21.7MB；三套动画资源全部前置。
8. 无障碍不足：结果区无 aria-live、历史列表无方向键、正文对比度约 2.5:1、错误重试用内联 onclick。
9. WebGL 初始化探测 bug（审计中新增发现）：在真实 canvas 上 getContext 后调用 loseContext()，同一 canvas 再次 getContext 返回的是已丢失上下文（precision=null），three.js 创建渲染器必然抛错，于是**永远静默回退到 Canvas 2D**。

**P2：维护性**

10. dispose() 写了但零调用；setInterval 永不清理；无后台暂停。
11. package-lock 里残留 Capacitor 依赖（package.json 已无）。
12. 无 LICENSE。
13. master 与 origin/main 是两条无关历史，远端 main 已删但本地仍有陈旧引用。

## 2. 研究性学习 / 青科协视角

### 2.1 先纠正前提：赛制 2025 年已大改

中国科协 2025 年 1 月印发《全国青少年科技创新大赛实施办法（试行）》：

- 参赛对象收紧到 **15–24 周岁**，不再接受低龄段少年儿童；
- **全国赛不再评价创新作品**，改为现场科技挑战任务，考察知识应用、动手实践、创新思维、批判精神与团队协作；
- 选手须由**关联赛事（省赛等）推荐**；设科学道德与伦理审查，弄虚作假、他人过度参与、移花接木一票否决。

推论：

1. 作品评审实际发生在**市赛/省赛**；
2. 未满 15 周岁无法参加全国赛，目标应调整为市/省赛 + 研究性学习成果；
3. 即使进入全国赛，仍需现场展示省赛获奖作品并接受真实性审查，"能不能讲清楚"依然要过关。

### 2.2 评分尺子

### 2.5 推荐课题：移动端 WebGL 天气背景的渲染预算与自适应降级（★★★★★）

**研究问题**：在中低端手机上，动态天气背景的帧时间主要由哪些渲染因子决定？能否用少量设备侧特征预测"可持续画质档位"，并在主观画质不显著下降的前提下显著降低卡顿？

**假设**：

- H1：帧时间对像素数/Bloom/云层数的敏感度远高于粒子数；
- H2：启动后 1–2 秒采样 + GPU 字符串/DPR/核数可预测稳定档位（准确率 > 80%）；
- H3：预算调度相比固定高画质与"仅裁粒子"，p95 帧时间降低 ≥30%，主观评分无显著下降。

**变量设计**：

| 类型 | 内容 |
|---|---|
| 自变量 | 分辨率缩放 0.5/0.75/1.0；Bloom 开/关；云层 4/2；雨粒子 1500/400；DPR 上限 1/2 |
| 因变量 | 平均 FPS、p95 帧时间、掉帧率（>1.5×刷新间隔）、首帧时间、JS 堆、主观 MOS 1–5 |
| 控制 | 同一页面、同一网络、同亮度、充电状态、预热 60 秒、每配置 3×30 秒 |
| 样本 | 6–8 台设备（低/中/高端，Android + iOS） |

**分析**：描述统计 + 多因素方差分析或对数线性回归 log(frame_time) ~ 像素 + Bloom + 云层 + 粒子；留一设备交叉验证；显著性 α=0.05，报效应量。**验证**：新旧策略 A/B，Wilcoxon 检验 + 主观配对评分。

**创新点表述（不要称首创）**：面向移动端 Web 的天气背景"设备画像 + 运行时反馈"两阶段渲染预算模型与阈值化降级策略；给出 6–8 类设备上的量化代价曲线，并将现有启发式策略的 p95 帧时间降低 X%。

**需要补的代码（约 300 行）**：

1. 渲染器 setQuality({resolutionScale, bloom, particles, cloudLayers, dprCap})（本轮已部分完成，见第 3 节）；
2. bench.html：URL 参数控制配置，跑 30 秒采集 rAF 时间戳，输出 JSON/CSV，附带 GPU 字符串、DPR、核数、UA；
3. 批量跑矩阵 + 结果导出。
